我在 Shop 查询接口里实现了缓存击穿保护，结果把缓存当锁用了：解锁时顺手把缓存删了。压测一跑，DB 像被踹了一脚，抖得很有节奏。
## 0. 背景：Day2 验收目标是什么？
- 目标接口：GET /shops/{shopId}
- 验收：
    1) 店铺不存在：返回错误码，且不打爆 DB（空值缓存）
    2) 热点店铺：并发下不打爆 DB（互斥/逻辑过期）

## 1. 现象：问题怎么暴露的？
- 并发压测时 DB 回源次数异常

## 2. 错误因果链：一个 Key 身兼两职，会发生什么？

这批问题是让 Codex 帮我审代码时一起挖出来的。核心错误只有一个：`lockKey` 用了 `CACHE_KEY_PREFIX`，于是 `cache:shop:{id}` 既当缓存、又当锁。顺着它往下推，会同时引发四类事故：

| 起点 | 过程 | 结果 |
|---|---|---|
| 缓存存在 | `SETNX(cache:shop:1, "1")` 失败 → 永远抢不到锁 → 永远进不了正常回源逻辑 | `shop` 一直是 null，逻辑分支直接走歪 |
| 缓存不存在 | 抢锁成功，锁值 `"1"` 被写进缓存 Key | 后续读缓存读到垃圾数据 `"1"` |
| 并发 miss | 抢锁失败的线程，走了“写空值缓存”的分支 | 真实店铺被缓存成不存在 → 假 404 |
| 解锁 | `unlock` 删除的是缓存 Key | 热点缓存被反复删掉，持续抖动并击穿 DB |

修复后，缓存和锁在物理上隔离：

- 缓存 Key：`cache:shop:{id}`，存真实 JSON
- 锁 Key：`lock:shop:{id}`，存锁占用标记

这属于缓存并发的底层卫生：锁是锁，缓存是缓存。

## 3. 根因清单（按严重级别）
### 3.1 Critical：锁 key 与缓存 key 混用
- 现象：unlock 可能误删缓存，导致缓存抖动
- 后果：热点击穿 → DB 抖动
- 修复：lockKey 与 cacheKey 分前缀

### 3.2 Critical：并发 miss 抢不到锁却写空值缓存（假404）
- 现象：真实有数据却被缓存为空
- 后果：长时间错误 404
- 修复：拿不到锁就 sleep + 重读缓存，不写任何缓存

### 3.3 Medium：lon/lat 未判空导致 NPE
- 现象：不传定位参数直接 500
- 修复：lon/lat 与 shop 坐标双向判空

### 3.4 Low：type 判空缺失导致 NPE / 错误码不清晰
- 修复：type 为空返回明确错误码

> 注：如果你的入口实际是 ShopServiceImpl#getById，还需要补齐 shopId/status/typeName/空值缓存等校验。

## 4. 最小补丁：改动点（只贴关键 diff）
- 1) lockKey 前缀修正
- 2) tryLock 失败的处理：sleep + 重读缓存
- 3) miss 回源后写入逻辑过期缓存 / 空值缓存
- 4) lon/lat 判空

## 5. 回归测试：怎么证明真的修好了？
### 5.1 不存在店铺：防穿透
- 删除缓存 key
- 并发请求不存在 shopId
- 预期：DB 只回源一次（或极少），后续命中空值缓存

### 5.2 热点店铺：防击穿
- 删除缓存 key
- “瞬间并发”请求同一 shopId（不要慢爬升）
- 预期：DB 回源次数≈1，其余等待锁或读缓存

### 5.3 lon/lat 缺省
- 只传 shopId
- 预期：200，distance 为空

## 6. 沉淀：Shop 查询接口容错点清单（可复用）
- 容错点01：锁 key 与缓存 key 必须隔离
- 容错点02：抢不到锁禁止写空值缓存
- 容错点03：逻辑过期必须保证首次建缓存
- 容错点04：经纬度可选参数要双向判空
- 容错点05：type 可能脏数据要判空
- 容错点06：status 校验必须在缓存层/业务层明确
